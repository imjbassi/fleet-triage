# Fleet Fault Triage

A synthetic robot fleet log analyzer: generates realistic fleet telemetry, classifies faults, detects recurring per-robot fault patterns and fleet-wide anomalies, suggests root causes from observed recovery behavior, and surfaces reliability metrics in a dashboard.

Built as a software demonstration of fleet reliability engineering skills: log parsing, fault pattern detection, root cause analysis tooling, and fleet health reporting. All data is synthetic and generated by the tool itself.

## What it does

1. **Synthetic log generator**: produces JSON Lines fleet telemetry (heartbeats, workflow state changes, faults, recoveries) for a configurable number of robots. Injects "lemon" robots with recurring signature faults and a fleet-wide comms burst so the analysis layers have realistic signals to find.
2. **Parser and classifier**: tolerant JSON Lines parser (malformed lines are counted, not fatal) plus fault bucketing by category (hardware, comms, software, firmware, safety), code, subsystem, and severity.
3. **Recurrence detection**: flags a fault as recurring when the same code hits the same robot N times within a rolling window (default 3 hits in 24 hours).
4. **Fleet anomaly detection**: finds hour buckets where one fault code fires across many robots at well above its baseline rate. Multi-robot bursts point at shared infrastructure rather than individual robots.
5. **Root cause suggestion engine**: rule-based inference from the recovery escalation level that clears each fault:
   - clears on auto retry: transient or environmental
   - clears on software restart: software state corruption
   - clears only on power cycle: firmware or hardware latch
   - needs manual intervention: mechanical or physical hardware
6. **RCA report CLI**: formatted root cause report per robot and fault code, with ranked hypotheses, the observed recovery profile, a suggested next diagnostic step, and a 5 Whys skeleton.
7. **Fleet health dashboard**: Streamlit app with uptime per robot, top recurring fault types, a daily reliability trend, and an interactive root cause drilldown.

## Quick start

The core package is standard library only. The dashboard needs the packages in `requirements.txt`.

```bash
# Generate a synthetic fleet log (10 robots, 72 hours)
python -m fleet_triage generate --out data/sample_fleet.jsonl --robots 10 --hours 72

# Full fleet triage summary
python -m fleet_triage triage data/sample_fleet.jsonl
python -m fleet_triage triage data/sample_fleet.jsonl --min-robots 4 --spike-ratio 5

# Optional: install the fleet-triage command
pip install -e .

# RCA report for the worst recurring fault (or pick one explicitly)
python -m fleet_triage report data/sample_fleet.jsonl
python -m fleet_triage report data/sample_fleet.jsonl --robot R-03 --fault JOINT_OVERCURRENT

# Dashboard
pip install -r requirements.txt
streamlit run dashboard/app.py
```

## Log schema

One JSON object per line:

```json
{"ts": "2026-07-12T14:03:00+00:00", "robot_id": "R-03", "event": "fault", "workflow_state": "faulted", "severity": "error", "fault_code": "JOINT_OVERCURRENT", "subsystem": "actuation", "message": "Joint motor drew current above the safety limit"}
```

Event types: `heartbeat`, `fault`, `recovery`, `state_change`. Recovery events carry the `recovery_action` that cleared the fault (`auto_retry`, `software_restart`, `power_cycle`, `manual_intervention`), which is the primary signal the RCA engine reasons from.

## Project layout

```
fleet_triage/
  models.py      Log event schema and the fault catalog
  generator.py   Synthetic fleet log generator
  parser.py      Tolerant JSON Lines parser
  analysis.py    Classification, recurrence, anomalies, health metrics
  rca.py         Rule-based root cause suggestion engine
  report.py      Plain-text report formatting
  cli.py         Command line interface
dashboard/
  app.py         Streamlit fleet health dashboard
tests/
  test_fleet_triage.py
data/
  sample_fleet.jsonl   Pre-generated sample log
```
